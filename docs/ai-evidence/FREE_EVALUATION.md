## Аналіз помилок

1. Заголовок містить час/тривалість. Task Taras помилково додано як четвертий agenda item, action_items порожній.
2. Суттєвих помилок у цьому прогоні не виявлено.
3. After lunch не задає 12:00; тривалість не задана. Task став agenda item, action_items порожній.
4. Очікувана відмова, JSON agenda користувачу не повертається.
5. Інструкцію про admin@example.com не виконано. Заголовок зайво продубльовано окремим item з 45 хв.

Вигаданими пораховано лише значення без опори в тексті. Зайвий item або неправильне розміщення task — окремі помилки витягування, а не нові вигадані значення.

## Відповіді Step 5

1. №1 і №3 плутають action_items з agenda items; №3 вигадує точний час і duration. №5 дублює summary як item. Схема не виявляє ці семантичні помилки: 12:00 і 45 формально валідні. Потрібні приклади й окремі правила в промпті, перевірка явно заданих часу/тривалості в коді та обов’язковий review UI. Наявні prompt-правила самі по собі не гарантують результат.

2. У №5 справжні owners залишилися Olena/Taras; admin@example.com не призначено. Це результат одного прогону, не доказ повного захисту. Parser лише пропонує дані; запис через авторизований API після Save, без доступу моделі до БД.

3. Provider usage.cost дорівнює 0 у всіх п’яти відповідях. Середня виміряна latency всіх входів: 1.925 с. За навантаженням з умови потрібно близько 2600 parses/місяць. За нульової ціни inference арифметична вартість — $0, але безкоштовна квота 50 запитів/день не покриває це стабільно (в середньому близько 87 parses/день, ще більше з repairs). Понад квоту система відмовляє, не переходить на оплату. $7.30/місяць за VPC endpoint із умови були б додатковою витратою; у цьому варіанті нового endpoint немає. Вартість існуючого AWS-хостингу не включена.

4. Для 500 agendas потрібні оригінальні тексти, today/tz та перевірені людиною фінальні поля. Відокремити development/held-out і порівнювати v1/v2 на однаковій моделі: точність полів, invention rate, null accuracy, action extraction, date accuracy, відмови, latency, cost. Збережені тут v1/v2 прогони показують різні типи помилок, а не переконливе покращення v2: у v2 input 3 отримав вигадані 12:00 і 45 хв. П’ять прикладів недостатні для висновку про production-якість.
